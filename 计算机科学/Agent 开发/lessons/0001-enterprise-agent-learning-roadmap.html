第一课：企业级 Agent 最短学习路线

目标不是“会调用大模型”，而是能把概率性模型放进一个可靠、可控、可审计的后端系统。

最短路径：先手写一次 Agent Loop，再用框架重写；先完成单 Agent 工单闭环，再学习多 Agent。

一条贯穿项目

八周只做一个“企业工单助手”：读取员工问题，查询知识库和工单系统，生成处理方案；普通查询自动完成，写操作必须经过权限检查和人工审批。

阶段 1：协议与最小循环

第 1-2 周

掌握消息、Token、结构化输出、工具调用和流式响应。不用 Agent 框架，手写带最大轮数、总超时和重复调用检测的循环。

验收：模型能自主查询工单，并在没有更多工具调用时正常退出。

阶段 2：业务能力

第 3-4 周

实现工具契约、权限、幂等、会话记忆和带引用的 RAG。工具返回结构化错误，不把异常文本直接交给用户。

验收：回答可追溯到知识来源，重复写请求不会产生重复工单。

阶段 3：可靠性

第 5-6 周

补齐追踪、评测、成本预算、模型降级和安全护栏；随后使用 LangGraph 或 Eino 重写状态管理与检查点。

验收：20 条固定评测可重复运行，每次回归能看到质量、延迟和成本变化。

阶段 4：企业上线

第 7-8 周

加入人工审批、断点恢复、租户隔离、SSE 流式接口、Redis/PostgreSQL 状态存储、容器化和发布策略。

验收：进程重启后任务可恢复，高风险操作未经审批不能执行。

每天如何学得更快

时间 动作 产出
20 分钟 阅读一段官方资料，只记协议和边界 三个要点
60 分钟 给贯穿项目增加一个可运行能力 代码与测试
20 分钟 构造超时、越权、幻觉或重复调用 失败证据

第一周只学这些

  1. 大模型调用不是普通函数调用：输出具有概率性。
  2. 工具调用（Tool Calling）只是模型提出调用申请，真正执行工具的是你的代码。
  3. 结构化输出必须经过 Schema 和业务规则校验。
  4. Agent Loop 必须有最大轮数、总超时、预算和退出条件。
  5. 任何写操作都必须经过权限检查、幂等保护和审计。

不要过早学习

  • 多 Agent 角色扮演
  • 复杂 Prompt 技巧合集
  • 同时学习多个 Agent 框架
  • 在没有评测集时反复“调感觉”
  • 把大模型直接连接生产数据库

查看答案

权限校验和幂等保证必须由确定性后端执行。分类、解释和检索决策可以交给模型，但要有置信度、范围和失败兜底。

课后任务

完成一个不依赖框架的最小工单 Agent：提供 get_ticket 与 search_kb 两个只读工具，限制最多调用 5 轮，总执行时间不超过 30 秒，并输出每轮工具名称、参数、耗时和结果摘要。

主阅读材料：Go/Python 后端工程师转 Agent 开发实战教程第三章。官方补充：Anthropic: Building effective agents。

完成练习后，把代码或运行日志交给 Agent 复核；下一课将针对工具调用循环中的真实错误继续推进。
